# 図解方針(Claude Artifactsの活用)

最終更新: 2026-08-30

[`02_lessons-from-atlas.md`](./02_lessons-from-atlas.md)で確認した通り、Atlasの最大の弱点は「図解を作るコストが高く、後回しにされ続けたこと」。notesではClaudeのArtifact機能を使って図解の作成コストを下げ、執筆フローに組み込むことを基本方針とする。

## 基本方針

- 図は文章の補足ではなく、理解の中核として扱う。構造・フロー・階層・状態遷移・比較など、文章より図で示した方が伝わる内容には、Atlasのように「枠だけ用意して中身は空(または後回し)」にしない
- 図はClaudeとの会話の中で作成するが、**claude.aiには公開しない**。Artifactとして公開してから改めてアプリ内に実装し直す二度手間を避けるため、最初からHTMLとしてプロジェクト内に直接書き出す
- `artifact-diagramming`(図解のSVG技法)スキルの技法は参考にしつつ、`artifact-design`が前提とするライト/ダーク両テーマ対応は不要(理由は下記「デザイン統一」参照)

## 執筆フロー

1. 本文を執筆する
2. 図解が必要な箇所を洗い出す(「これは文章だけで伝わるか?」を都度自問する)
3. 該当箇所を単体で完結したHTML(外部CDN依存なし)として直接作成する
4. ページに組み込む(組み込み方式は下記「組み込み方式」参照)

Atlasの反省(§[`02_lessons-from-atlas.md`](./02_lessons-from-atlas.md))を踏まえ、「後で図を足す」という先送りを前提にしない。ステップ2〜4を本文執筆と同じコミット・同じレビュー単位で完結させる。

## 組み込み方式(決定)

Atlasが`.html`ファイルの表示に使っている`<iframe sandbox srcdoc="...">`方式(Header/Sidebarは維持したままMain領域に埋め込み、Atlas本体のCSSと衝突させない)をそのまま流用する。図解のHTMLはリポジトリ内の通常のプロジェクトファイルとしてコミットし、claude.aiのArtifact URLには依存しない。オフラインでも閲覧でき、更新もリポジトリ内の編集だけで完結する。

## デザイン統一(最小限)

Artifactの表現力・レイアウトの自由度を邪魔しないよう、揃えるのは「外枠」に相当する最小限のトークンのみとし、中身(構図・配色・図の種類)は都度自由に作る。

| 揃える項目 | 値の出どころ(Atlas `globals.css`) |
|---|---|
| 背景色 | `--background` |
| 基本文字色・フォント | `--foreground` / `--font-sans`(Geist Sans + 日本語フォールバック) |
| アクセント色(1色、強調・ハイライト用) | `--primary` / `--accent`(緑, `oklch(0.85 0.29 142)`) |
| 角丸の基準値 | `--radius`(0.5rem)系のスケール |

揃えない項目: レイアウト・構図、ノード形状、データ区分用の複数色パレット、アイコン、アニメーション。

Atlasはライト/ダーク切り替えに対応していない(常に黒背景固定)ため、ダーク1色のパレットを渡すだけでよく、通常のArtifact設計指針が求める光/暗両対応は不要。

## 品質基準

- Diagramのような「枠+キャプション」だけのラッパーに図の役割を持たせない。中身に実質的な視覚表現(フローチャート・比較図・階層図・状態遷移図など)を必ず伴わせる
- 1ページに最低1つ、主要概念ごとに対応する図解を用意することを目安にする(Atlasは516ページ中130ページ=約25%にとどまっていた)
